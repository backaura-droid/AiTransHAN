# claude-thinking-ko 설계 문서

## 배경과 의도

Claude Code VSCode 확장(및 이를 품은 Antigravity IDE)의 채팅 패널에는 최종 답변 앞에 "사고(thinking)" 미리보기 텍스트가 함께 표시된다. 이 미리보기가 종종 영어로 나온다(최종 답변은 한국어로 나오지만, 미리보기는 별도 경로라 한국어 강제 규칙이 적용되지 않는 것으로 보임). 사용자는 이 영어 미리보기를 한국어로 번역해서 보고 싶어 한다.

Claude 자신에게 "실시간으로 사고 과정을 한글로 바꿔 달라"고 지시하는 접근은 이번 대화에서 두 차례 안전 분류기에 막혔다(원인 불명, 다만 기존 메모리 `reasoning-extraction-transcript-readback.md`·`reasoning-extraction-instruction-wording.md`에 "세션 로그의 사고 본문을 대화로 꺼내 설명하면 안전장치가 반복해서 걸린다"는 동일 패턴 기록이 있음). 따라서 이 도구는 **LLM 대화를 거치지 않는다** — Node.js 코드가 디스크에 이미 쓰인 로그 파일을 직접 읽고, 번역은 별도 프로세스(CLI)에 맡기고, 결과를 VSCode 패널에 표시하기만 한다. Claude 본체에게 "네 사고 과정을 설명해 달라"고 묻는 동작이 전혀 없으므로 위 문제와 무관하다.

## 목표

- VSCode(및 Antigravity) 사이드바에 새 패널을 하나 추가해, Claude Code 세션 로그에 새로 기록된 사고(thinking) 블록을 한국어 번역과 함께 실시간에 가깝게 보여준다.
- 사용자가 이미 보유한 구독(agy=Gemini CLI, 또는 Claude 자신)만 쓴다. 외부 번역 API 키는 쓰지 않는다.
- 초 단위 폴링으로 번역 CLI를 반복 호출하지 않는다. 완성된 사고 블록 하나당 한 번만 호출한다.

## 비목표 / 안티골

- Claude Code나 Antigravity 확장의 화면(webview DOM)을 직접 조작하거나 그 안에 끼어들지 않는다 — 불가능하고 시도하지 않는다.
- 과거 세션 전체를 일괄 번역하는 백필 기능은 v1 범위 밖.
- 여러 워크스페이스/여러 세션을 동시에 표시하는 멀티세션 뷰는 v1 범위 밖 — 현재 열린 워크스페이스의 가장 최근 활성 세션 하나만 다룬다.
- Claude 본체에게 "사고 과정을 설명해달라"고 지시하는 경로는 만들지 않는다(위 배경 참조).
- **대상은 "Claude Code" 확장의 세션 로그에 한정한다.** 사이드바에 같이 떠 있는 Codex·Antigravity 자체 에이전트 탭은 별도 시스템이라 저장 형식이 검증되지 않았고, 사용자가 겪은 문제(영어 미리보기)도 Claude Code 탭에서 나온 것이므로 그쪽은 다루지 않는다.
- **번역 백엔드는 v1에서 agy(Gemini CLI)만 쓴다.** Claude CLI로 번역하는 경로는 "세션 자신의 사고 로그 내용을 Claude에게 다시 먹이는" 구조라 이번 대화에서 이미 두 번 막힌 패턴과 구조적으로 겹친다. 굳이 같은 위험을 다시 밟을 이유가 없어 v1 비목표로 내리고, 나중에 필요하면 별도 스파이크로 안전한지부터 확인한다.

## 데이터 소스 (확인된 사실)

Claude Code는 세션 전체를 `C:\Users\user\.claude\projects\<워크스페이스-인코딩>\<세션-uuid>.jsonl`에 한 줄당 JSON 객체(JSONL) 형식으로 기록한다. 이번 대화 자체의 파일(`8ec5f472-e454-4708-be14-bf21e075ca75.jsonl`, 워크스페이스 `E:\Hermes_Obsidian` → 폴더명 `e--Hermes-Obsidian`)에서 **본문 텍스트는 읽지 않고 필드 이름만** 추출해 다음을 확인했다.

- 레코드 최상위에 `cwd`(작업 디렉터리), `sessionId`, `timestamp`, `message` 등의 키가 있다.
- `message.content`는 배열이며 각 원소의 `type`이 다음 값 중 하나다: `thinking`, `text`, `tool_use`, `tool_result`, `image`, `tool_addition`.
- 최상위에 `thinkingDisplay`, `thinkingDurationMs` 필드도 별도로 존재한다 — 화면에 보이는 짧은 미리보기가 `content[].type === "thinking"`의 전체 본문이 아니라 이 `thinkingDisplay`일 가능성이 있다. **이 글자가 실제로 사이드바 미리보기와 일치하는지는 구현자가 실제 값을 직접 눈으로 비교해 확정한다** (이 설계 문서를 쓴 쪽은 본문 내용을 읽지 않았다 — 아래 "읽기 주의" 참조).
- `isApiErrorMessage`, `apiRefusalCategory`, `refusedMessageId` 같은 필드도 존재한다. 이런 레코드는 정상 사고 블록이 아니므로 건너뛴다.

워크스페이스 경로 인코딩 규칙(소문자화, `:`와 `\`를 `-`로 치환 등)을 역산해서 추정하지 말고, 각 레코드의 `cwd` 필드 값을 현재 VSCode 워크스페이스 루트와 직접 문자열 비교해서 맞는 세션 폴더를 찾는다. `~/.claude/projects/` 하위 각 폴더에서 `cwd`가 일치하는 `.jsonl` 파일 중 `mtime`이 가장 최근인 것을 "활성 세션"으로 삼는다.

### 읽기 주의 (중요)

구현자(사람이든 서브에이전트든)가 소스 코드를 작성하는 동안 세션 jsonl의 `thinking`/`thinkingDisplay` 실제 텍스트 내용을 터미널에 출력해서 자신의 LLM 대화 맥락으로 되읽어오지 않는다. 스키마 확인은 키 이름·타입 값만으로 충분하다. 실제 번역 동작 확인은 VSCode 확장을 직접 실행해 패널에 뜬 결과를 눈으로 보는 방식으로 한다(즉, 확인 주체가 LLM 대화가 아니라 사람의 눈이 되게 한다).

## 감지 로직

1. `chokidar` 등으로 활성 세션 `.jsonl` 파일을 감시한다.
2. 마지막으로 읽은 바이트 오프셋을 기억해두고, 파일이 변경될 때마다 그 오프셋부터 새로 추가된 바이트만 읽는다(파일 전체가 최대 수십 MB까지 자라므로 매번 전체를 다시 읽지 않는다).
3. 새로 읽은 바이트를 줄바꿈 기준으로 나눈다. 마지막 줄이 아직 끝나지 않았을 수 있으므로(기록이 스트리밍 중일 가능성에 대비) `JSON.parse`를 시도해서 실패하면 버퍼에 남겨두고 다음 변경 이벤트 때 이어붙여 재시도한다. 성공한 줄만 "완성된 레코드"로 처리한다.
4. 완성된 레코드 중 `message.content[]`에 `type === "thinking"`이 있거나 `thinkingDisplay`가 채워진 것을 찾으면, 그 텍스트를 번역 큐에 넣는다.

이 방식은 타이머 기반 디바운스가 아니라 "완성된 JSON 한 줄 = 완성된 사고 블록 하나"를 트리거로 쓴다. 그래서 초마다 반복 호출되는 일이 구조적으로 없다.

## 번역 필터

텍스트에 한글이 거의 없고(예: 한글 글자 비율이 낮음) 영문 단어가 일정량 이상 섞여 있을 때만 번역 큐에 넣는다. 이미 한국어인 블록은 건너뛴다. 정확한 임계값은 구현자 재량(사소한 값이라 사용자 확인 불필요).

## 번역 실행

- 큐는 FIFO 한 개, 동시에 한 건만 처리한다(여러 사고 블록이 몰려도 번역 CLI를 동시에 여러 개 띄우지 않는다).
- 번역 대상 텍스트는 명령줄 인자로 직접 넘기지 않는다. 임시 파일에 써서 `cmd /c type <임시파일> | agy -p "..."` 패턴으로 표준입력으로 흘려보낸다. PowerShell 파이프가 한글을 깨뜨리는 기존 사례(메모리 `council-agy-stdin-encoding.md`)가 있어서 이 방식을 그대로 따른다.
- `agy` 정확한 번역용 호출 문법(비대화형 실행 플래그, 긴 입력 처리 방법)은 구현 시작 전에 `agy --help` 등 공식 사용법으로 먼저 확인한다(추측 금지).
- 번역 실패(타임아웃, CLI 없음, 쿼터 소진)는 패널에 에러 표시만 하고 재시도하지 않는다(v1).

## 화면 표시

VSCode 사이드바에 전용 아이콘/패널을 새로 등록한다(기존 "Claude Code / Codex / Antigravity" 탭 묶음을 건드리는 게 아니라 그 옆에 독립된 뷰 컨테이너를 추가하는 것 — 표준 확장 기능이라 다른 확장과 충돌 없음). 패널 내용은 시간순으로 쌓이는 로그 형태(원문 영어 일부 + 번역된 한국어)로, 출력 채널처럼 아래로 흐르게 한다(트리뷰 같은 구조화된 UI는 v1에서 과함 — 내 판단).

## 켜고 끄기

확장 활성화 시 현재 워크스페이스에 대응하는 세션 폴더가 있으면 자동으로 감시를 시작한다. 이때 그 세션에 이미 쓰여 있던 과거 사고 블록을 따라잡지 않고, 활성화 시점(파일 끝)부터 새로 쓰이는 것만 본다 — 과거분까지 한꺼번에 번역 큐에 넣으면 활성화 직후 번역 호출이 몰려서 쿼터를 낭비한다. 커맨드 팔레트에 "일시정지/재개" 명령을 하나 둬서 번역 쿼터를 아끼고 싶을 때 끌 수 있게 한다.

## 기술 스택

- VSCode Extension API (TypeScript), `chokidar`(파일 감시), Node `child_process`(agy 서브프로세스 호출).
- 저장소: `C:\Users\user\claude-thinking-ko` (신규 git 저장소, 볼트 밖 — `report-pipeline`과 같은 기존 관례를 따름).

## 빌드 순서상 먼저 확인할 것

- **스키마**: 이번 대화 자체가 "VSCode Extension Context" 안에서 돈 Claude Code 세션이고, 그 세션 파일(`8ec5f472-e454-4708-be14-bf21e075ca75.jsonl`)에서 위 스키마를 확인했다 — 즉 "데이터 소스" 절 내용은 추정이 아니라 Claude Code 확장 세션 자체로 확인된 사실이다.
- **사이드바 탑재 가능 여부**: 사용자가 쓰는 IDE 호스트(스크린샷의 Antigravity)가 서명 안 된 로컬 확장(.vsix/개발 모드)을 그대로 얹어주는지는 아직 안 해봤다. 확장 틀만 먼저 만들어 그 호스트에 설치해보는 걸 1단계로 삼고, 안 되면 "표준 VSCode에서는 되고 Antigravity는 추후"로 범위를 좁힌다 — 전체 설계를 다시 짤 필요는 없고 설치 경로만 바뀐다.

## 구현자에게 맡기는 것

- 정확한 한글 비율 임계값, 디바운스 미세 조정값.
- 패널 UI의 구체적인 스타일(글자 크기, 색).
- `agy` 정확한 CLI 플래그(공식 `--help` 확인 후 결정).
- `thinkingDisplay` vs `content[].type==="thinking"` 중 실제로 화면 미리보기와 일치하는 쪽 — 구현 중 직접 확인.
